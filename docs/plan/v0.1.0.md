## 目的

家族共有のオフライン家計簿を作りながら CRDT を学ぶ。v0.1.0 は学習の 1 週目に対応し、ライブラリを使わずに次を自作して仕組みを理解する（要件 7）。

1. 増えるだけのカウンタ（G-Counter）
2. 後勝ちレジスタ（LWW-Register 相当）
3. 学ぶ概念: 交換法則・結合法則・冪等性

## 対象範囲

- メモリ上の 3 レプリカ（A / B / C）による独立更新と同期のシミュレーション
- 状態全体を交換する方式での merge
- 固定例と seed 付きランダム操作による自動テスト
- 配送順の入れ替え・重複配送・古い状態の遅延配送・分断後再同期を想定した収束確認

## 設計方針

### 全体

- 実装言語: TypeScript（`strict`）
- ライブラリなしで CRDT を自作する
- 同期は「状態全体を交換して merge する」方式とする（差分同期は後続バージョン）
- 実データは使わず、架空のレプリカ ID と値だけを用いる

### G-Counter（増えるだけのカウンタ）

- 状態はレプリカ ID ごとの非負整数の写像
- 加算は自分のレプリカ成分だけに行う
- 表示値（読取値）は各成分の合計
- merge はレプリカ ID ごとに max を取る
- 受信した相手の値を単純加算してはならない（二重計上になる）

学習メモ: 各レプリカは自分の加算だけを記録する。merge で相手の成分を加算すると、同じ状態を複数回受け取ったときに二重計上になる。成分ごとの最大値を取れば、到着順や重複配送に依らず単調に増え、最終的に同じ写像へ収束する。

### 後勝ちレジスタ（LWW-Register 相当）

- 状態は `value` と stamp `(論理カウンタ, 一意なレプリカID)` を持つ
- 勝者は stamp の辞書順最大（論理カウンタ優先。同値ならレプリカ ID で決める）
- 受信後の新規書込みでは観測済みの最大論理カウンタを越える番号を使う
- 同一 stamp を別の書込みに再利用しない
- これは壁時計の「実時間の最後」を保証する意味ではない。決定的な順序で勝者を決める仕組みである
- 競合時に両方の値を残す方式ではない（片方の value だけが残る）

学習メモ: 競合すると敗者の value は失われる。履歴も残らない。壁時計の前後とも一致しないことがある。決定的な勝者選択である、とコードコメントにも記す。

## 受け入れ条件（v0.1.0 機能完了時）

計画どおり実装したあとに満たす条件です。

1. メモリ上のレプリカ A / B / C がそれぞれ独立に更新できる
2. 全変更が最終的に届いたあと、内部状態と読取値が 3 者で一致する
3. 配送順を入れ替えても最終状態が一致する
4. 同じ変更の重複配送でも状態が変わらない（冪等）
5. 古い状態の遅延配送や、分断後の再同期でも最終的に一致する
6. merge について交換法則・結合法則・冪等性を自動テストで確認できる
7. 固定例に加え、seed 付きランダムテストがあり、失敗時は seed と操作列で再現できる
8. 同期の途中経過で常時一致していることは要求しない（最終収束のみ）

要件ページの関係完了条件との対応は次のとおりです。

- 「3 つの端末の同期順を入れ替えても、最終状態が一致する自動テストが通る」
- 「同じ変更を 2 回受け取っても状態が変わらない」
- 「自作したカウンタと後勝ちレジスタが、ランダムな順番の操作でも常に一致する」

## 受け入れ条件とテストの対応

| 条件 | G-Counter | 後勝ちレジスタ |
| --- | --- | --- |
| 1 独立更新 | `G-Counter acceptance` / `allows independent updates on replicas A, B, and C` | `LWW-Register acceptance` / `allows independent updates on replicas A, B, and C` |
| 2 全変更到達後の一致 | `converges internal state and values after all changes arrive` | 同名 |
| 3 配送順入れ替え | `converges regardless of delivery order` | 同名 |
| 4 重複配送（冪等） | `is unchanged under duplicate delivery (idempotent merge)` | 同名 |
| 5 遅延・分断後再同期 | `converges after delayed old state and after partition healing` | 同名 |
| 6 交換・結合・冪等 | `G-Counter merge algebra` の 3 件 | `LWW-Register merge algebra` の 3 件 |
| 7 seed 付きランダム | `G-Counter seeded random` / `converges for seeded random operation sequences`（試行 50、BASE_SEED `0xc0ffee`） | `LWW-Register seeded random`（試行 50、BASE_SEED `0xbadc0de`）。失敗時は seed と操作列を Error に含める |
| 8 途中一致は要求しない | ランダムテストは操作列のあとで最終 merge してからだけ一致を見る | 同左 |

## 実行コマンド

パッケージマネージャは pnpm のみです（lockfile: `pnpm-lock.yaml`）。mise 利用時は先頭に `mise exec --` を付けます。

```bash
# 依存関係のクリーンインストール
mise exec -- pnpm install --frozen-lockfile

# 品質チェック一式（typecheck / lint / fmt / deadcode / coverage / build）
mise exec -- pnpm check

# 非 watch のテスト（ファイル指定）
mise exec -- pnpm test run src/g-counter.test.ts
mise exec -- pnpm test run src/lww-register.test.ts
mise exec -- pnpm test run src/env-smoke.test.ts
```

`src/env-smoke.test.ts` は環境確認専用であり、収束テストではありません。収束の根拠は上記の G-Counter / LWW テストです。
