## 目的

同時編集が日常的に起きる前提で、次を実装する。

- 要件 3: 同じ明細の別項目の同時修正は両方残り、同一項目は一方に決まる。決まり方を説明できる
- 要件 4: 削除と編集がぶつかったとき、**編集優先**にする
- 要件 5: 合計・残高は保存せず明細から計算する。カテゴリ予算は足し引き（PN-Counter）で同時変更を両方反映する
- 要件 6: 二重入力相当を重複候補として表示する。自動削除しない

## 対象範囲

- 明細をフィールド単位で更新できるネスト `Y.Map`
- 同一フィールド競合の説明（壁時計ではない）
- 削除×編集の編集優先（墓石 + rev）
- 派生合計の計算（永続化しない）
- カテゴリ予算の PN-Counter
- 重複候補の検出と表示

## 非対象（このバージョンではやらない）

- 明細ごとの変更履歴 UI（[v1.0.0](./v1.0.0.md)）

## 着手前確認（観測結果）

### 1. 固定した形

| 層 | 形 |
| --- | --- |
| 明細マップ | 親 `Y.Map("entries")`。キーは明細 ID。値はネスト `Y.Map` |
| 子フィールド | `id` / `date` / `amount` / `category` / `memo` / `enteredBy` / `rev`（端末ごとの改訂カウンタ） |
| 削除表現 | 親キーは消さない。`Y.Map("tombstones")` に、削除時点の `rev` スナップショットを置く |

### 2. Yjs 既定動作（公式・ソース）

- [INTERNALS.md](https://github.com/yjs/yjs/blob/main/INTERNALS.md): Map はキーごとのエントリ列で、各キーの最後のエントリが残る。Item ID は `(clientID, clock)`（Lamport）。壁時計ではない
- `Item#integrate`（`node_modules/yjs/src/structs/Item.js`）: 同じ origin の並行挿入では、より大きい `clientID` が右側へ行き、Map では末尾が残る
- 観測テスト `src/ledger/yjs-defaults.test.ts`: 親キー削除と並行する子フィールド編集では、配送順に依らずエントリが消える。したがって「同じキーへの delete と set」規則を明細削除×子編集に当てはめない

### 3. 配送順を入れ替えても既定結果が同じことの観測

- 別フィールド並行 set → 両方残る（順序非依存）: `conflict.test.ts` / `yjs-defaults.test.ts`
- 親キー削除 vs 子編集 → 両方の順でエントリ消失: `yjs-defaults.test.ts`
- 墓石+rev の編集優先 → 両方の順で明細が残る。単独削除は非表示: `conflict.test.ts`

### 4. 合意した方針

削除×編集は **編集優先**（ユーザー決定）。通常の単独削除は非表示のまま。

## 確定した設計

### 同一フィールドの勝者（要件 3）

同じ子フィールドへの並行 `set` の勝者は、壁時計ではなく Yjs の Item ID（`clientID` と論理 `clock`）に基づく。同じ integration origin では、より大きい `clientID` の Item が Map の末尾として残る（`Item#integrate` + Map の「各キーの最後のエントリ」）。因果的に後続する `set` は通常どおり後勝ちになる。全レプリカで同じ最終値に収束する。

### 削除×編集（要件 4）

1. 削除時に `rev` のスナップショットを `tombstones[entryId]` へ書く（親キーは残す）
2. フィールド編集は該当端末の `rev[deviceId]` を増やす
3. 表示: 墓石が無い、または現在の `rev` が墓石をいずれかの成分で上回る → 見える（編集優先）
4. 墓石の `rev` 以下のまま → 非表示（単独削除）

明細全体を 1 回の set で置き換える方法は使わない（要件 3 を壊す）。

### 予算（要件 5）

平坦な `Y.Map("budgetP")` / `Y.Map("budgetN")`。キーは `${category}\0${deviceId}`。各端末は自分のキーだけを増やす。値は ΣP − ΣN。カテゴリ単位のネスト Map を並行生成すると片方の木が消えるため、平坦キーにした。

### 重複候補（要件 6）

閾値:

1. 明細 ID が異なる
2. 日付が一致
3. 金額が一致
4. カテゴリ一致、または正規化メモが一致、または短い方（長さ ≥ 2）が長い方に含まれる

候補表示だけでは消さない。

### v0.3.0 からの移行

プレーンな明細オブジェクトは、起動時にネスト `Y.Map` へ昇格する（`migratePlainEntriesToNestedMaps`）。
