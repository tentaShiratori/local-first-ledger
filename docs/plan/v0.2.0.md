## 目的

端末ごとの CRDT ドキュメントに明細（日付、金額、カテゴリ、メモ、入力者）を持ち、ブラウザ内に保存する。電波がなくてもアプリを起動し、入力と閲覧ができる（要件 1）。

再読込での復元と、起動そのものをネットワークなしで行えることを分けて扱う。

## 対象範囲

- CRDT ライブラリの選定確定（Yjs）
- 明細を保持するドキュメント形状の最小定義
- ブラウザ内永続化（IndexedDB。公式経路 `y-indexeddb`）
- オフラインでのアプリ起動（Service Worker で静的アセットをキャッシュ）
- 一意な端末（レプリカ）ID の発行と保存
- 同一プロファイル複数タブの扱い（単一書き込み＋警告）と検証

## 非対象（このバージョンではやらない）

- 中継サーバーと端末間の差分同期（[v0.3.0](./v0.3.0.md)）
- フィールド競合・削除方針・予算カウンタ・重複候補・履歴 UI（後続）
- 認証、グラフ、銀行 API、ネイティブアプリ（プロジェクト全体の対象外）

## 確定した設計

| 項目 | 決定 | 根拠 |
| --- | --- | --- |
| CRDT ライブラリ | **Yjs**（npm `yjs`） | 人気で選定。測定日 2026-11-10、対象週 2026-11-03〜2026-11-09 の実測: npm 週間 DL は yjs 15,689,133 / loro-crdt 215,369 / @automerge/automerge 120,380 / automerge 11,418。GitHub stars は yjs/yjs 23,042 / automerge/automerge 6,723 / loro-dev/loro 6,283。索引の Automerge 推奨は採用しない |
| 永続化 | `y-indexeddb` の `IndexeddbPersistence` | [Yjs Offline / IndexedDB](https://docs.yjs.dev/getting-started/allowing-offline-editing) |
| オフライン起動 | Service Worker（`vite-plugin-pwa` の generateSW） | 同上。アセットをローカルキャッシュし、ネットワーク遮断後も入力画面へ到達する |
| 端末 ID | 初回起動で UUID を発行し `localStorage` に保存 | 以後のレプリカ識別に使う |
| 同一プロファイル複数タブ | **書き込みは 1 タブのみ**。他タブは明示警告を出し、入力フォームを無効化する | Web Locks API（`navigator.locks`）で排他 |

### Yjs 採用に伴う後続の設計負債（いまは実装しない）

索引が Automerge を推奨した主因は、要件 5 の `Counter` と要件 8 の文書履歴である。Yjs コアには専用 Counter 型がなく、明細単位の「誰がいつ何を」はアプリ設計の比重が大きい。後続バージョン（とくに [v0.4.0](./v0.4.0.md) の予算、[v1.0.0](./v1.0.0.md) の履歴）では、Counter 相当と履歴の取り方をそのバージョンの受け入れ前に書き直す。

## データ形状（実装）

正規の保存先は端末ごとの Y.Doc（`Y.Map("entries")`）。合計・残高は永続化しない（要件 5）。

明細フィールド:

- `id`（作成時に端末が発行）
- `date` / `amount` / `category` / `memo` / `enteredBy`

削除表現は [v0.4.0](./v0.4.0.md) まで持たない。入力者は家族の表示名選択であり、認証ではない。

主な実装置き場:

- `src/ledger/` … 端末 ID・明細・Y.Doc・永続化・タブロック
- `web/main.ts` … 入力・一覧 UI
- Service Worker … `vite-plugin-pwa` が `dist-app/` に生成

## 受け入れ条件と検証対応

| # | 受け入れ | 検証 |
| --- | --- | --- |
| 1 | ライブラリが文書上で選定済み（Yjs。Automerge 推奨からの変更理由あり） | 本計画と [索引](./README.md) |
| 2 | ネットワークを切った状態でアプリを起動できる | `pnpm verify:offline-tabs`（Playwright の `setOffline`。e2e 公開 API には offline が無い） |
| 3 | オフラインで明細を追加・閲覧できる | 同上（遮断後も一覧が残る）。通常の追加・閲覧は `pnpm e2e` |
| 4 | ブラウザを終了して開き直しても同じ端末の明細が復元される | `pnpm e2e`（リロード復元）と `src/ledger/persistence.test.ts`（IndexedDB） |
| 5 | 端末 ID が再起動後も同じ | `pnpm e2e` と `src/ledger/device-id.test.ts` |
| 6 | 複数タブが単一書き込み＋警告 | `pnpm verify:offline-tabs` と `src/ledger/tab-lock.test.ts`。e2e ランナー単体では複数タブを表現できない |

注意: `pnpm check` 成功は環境スモークであり、オフライン起動や永続化の証拠ではない。端末間同期や収束もこのバージョンでは主張しない（中継は [v0.3.0](./v0.3.0.md)）。
