## 目的

2 つのブラウザが中継サーバー経由で差分だけを送り合い、同じ状態になる。サーバーはドメインの中身を解釈せず、中継と保管だけを行う（要件 2）。

## 対象範囲

- クライアント間で Yjs 更新バイト列（差分）を交換する経路
- 中継サーバーの責務: バイト列の受け取り、保管、再接続時の引き渡し。明細 JSON へのパースや合計計算はしない
- 再接続時に欠けた更新を取得できること
- サーバー再起動後も、保管してある更新からクライアントが追いつけること
- 遅延・重複配送を想定した収束確認（2 レプリカ以上）

## 非対象（このバージョンではやらない）

- フィールド単位の競合 UI、削除方針、予算、重複候補、履歴表示（[v0.4.0](./v0.4.0.md) / [v1.0.0](./v1.0.0.md)）
- 明細の Y.Map 構造変更（[v0.4.0](./v0.4.0.md)）
- P2P 直結、暗号化、一般公開向け認証（発展または対象外）
- クラウドへの本番デプロイ、課金、常時公開（実施しない）

## 確定した設計

| 項目 | 決定 | 根拠 |
| --- | --- | --- |
| CRDT | Yjs | v0.2.0 で確定。更新は `doc.on('update')` / `Y.applyUpdate`（[Document Updates](https://docs.yjs.dev/api/document-updates)） |
| 通信 | WebSocket（Node の小さな自作中継。`ws`） | 双方向で差分を即時配送できる。`y-websocket` 公式サーバーは使わない |
| サーバー保管 | ドキュメント ID ごとに opaque な更新バイト列をファイルへ追記（length-prefixed） | サーバーは Yjs を import しない。Y.Doc を持たない。明細を読まない |
| 再接続 | ログ連番（seq）を付けて保存・配送。クライアントは最後に受け取った位置を保存し、再接続時はその位置以降だけを受け取る | オフライン中のローカル更新は未送信キューに永続化し、ack まで保持。重複適用は Yjs の冪等性で吸収 |
| 共有ドキュメント | 既定 ID `family-demo`（`?doc=` で上書き可）。端末 ID はレプリカ識別のまま | v0.2.0 の端末別ルーム名から共有 ID へ。空の共有ドキュメントへ、端末別の旧データがあれば 1 回だけ `encodeStateAsUpdate` で取り込む |
| 公開範囲 | ローカル / 閉じた検証環境のみ。認証なし | 一般公開しない旨を README・UI に明記 |

### 輸送プロトコル（概要）

1. クライアントが `subscribe { docId, fromSeq }` を送る
2. サーバーが `fromSeq` 以降の保管エントリを `entry { seq, updateBase64 }` で返す
3. ローカル更新は `push { updateBase64, clientMsgId }`。サーバーは追記して `ack` し、他購読者へ `entry` を配る
4. クライアントは ack / entry の seq から次の `fromSeq` を進める

### サーバー責務

| してよいこと | してはいけないこと |
| --- | --- |
| 接続の受け付けと切断の検知 | 明細フィールドの検証や書き換え |
| 更新バイト列の保存と返却 | 合計・残高・カテゴリの計算 |
| 再接続クライアントへの不足分配送 | 「正しい家計簿状態」への裁定 |
| Y.Doc の組み立てや yjs の import | （学習意図から外れるため行わない） |

### v0.2.0 からの移行

- 永続化ルーム名: `local-first-ledger:entries:${documentId}`（共有 ID）
- 旧: `local-first-ledger:entries:${deviceId}`
- 共有ドキュメントが空で、端末別の旧ルームに明細があるときだけ 1 回取り込む。フラグ `local-first-ledger:migrated-to:${documentId}` で再実行しない

## 受け入れ条件と検証対応

| # | 受け入れ | 検証 |
| --- | --- | --- |
| 1 | 2 クライアントがオンラインなら、一方の入力が他方に届き最終状態が一致する | `src/ledger/sync-relay.test.ts` と `pnpm verify:relay-sync` |
| 2 | 交換しているのは差分であり、サーバーはドメイン解釈をしない | 保管が opaque バイト列のみ。`src/relay/opaque.test.ts`（yjs を import しない）。同期テストの保管形確認 |
| 3 | 一時切断のあと再接続すると、欠けていた更新を取り込める | `sync-relay.test.ts`（双方オフライン入力→再接続）と `verify:relay-sync`（`setOffline` 中に追加） |
| 4 | サーバープロセスを再起動しても、保管分から同じ状態へ戻れる | `sync-relay.test.ts`（ファイル保管を残して再起動） |
| 5 | 同じ更新を重複して受け取っても状態が壊れない | `sync-relay.test.ts`（同一更新の二重適用） |

追加検証: 古い更新の遅延適用、3 レプリカの配送順入れ替えは同テストファイル。環境スモーク（`pnpm check`）は収束の証拠に使わない。

## 実行コマンド

```bash
mise exec -- pnpm relay
# 別端末でアプリ。例: http://127.0.0.1:5173/?doc=family-demo&relay=ws://127.0.0.1:8787
mise exec -- pnpm check
mise exec -- pnpm test run src/ledger/sync-relay.test.ts
mise exec -- pnpm test run src/relay
mise exec -- pnpm e2e
mise exec -- pnpm verify:offline-tabs
mise exec -- pnpm verify:relay-sync
```
