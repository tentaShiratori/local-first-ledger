# v1.0.0 人手 1 週間の受け入れ手順

エージェントは実データ投入・家族への連絡・実運用を行わない。この文書の記録欄は空欄のままリポジトリに置く。記入するのは人だけ。

## いまやること

1. 下の「開始前チェック」を上から順に済ませる
2. カレンダーで 7 日間の利用枠を決める（自分の 2 台、または家族と使う）
3. 毎日の記録表に、困ったことだけ短く書く
4. 7 日後に「終了チェック」を埋める
5. 受け入れ条件 4 を満たしたら `docs/plan/v1.0.0.md` の状態を人が更新する

## 対象と非対象

| 区分 | 内容 |
| --- | --- |
| 対象 | オフライン入力、復帰後の同期、削除と編集、履歴表示、重複候補の目視 |
| 使ってよいデータ | 架空の明細と表示名だけ（例: たろう / はなこ / じろう、コンビニ弁当 680 円） |
| 使ってはいけないデータ | 本物の家計・口座・カード番号・実在する家族の私的メモ |
| エージェントがしないこと | 実データ投入、家族連絡、監視、本番公開 |

## 毎日の使い方（最短）

1. 端末 A と端末 B で同じ `doc` と中継 URL を開く
2. どちらかをオフラインにして、架空の明細を数件入れる
3. オンラインに戻し、一覧と合計がそろうか見る
4. 同じ明細を両方で違うフィールドだけ編集し、両方の変更が残るか見る
5. 明細の「履歴」を開き、操作順と壁時計の切り替えが説明どおりか見る
6. 困ったことだけ下の表へ書く（なければ「なし」）

## つまずいたときの見方

1. 同期しない → 中継 URL と `doc` が同じか、タブ役割が writer かを見る
2. 合計が違う → まだ offline の端末がないか、削除が片方だけかを見る
3. 履歴の順番が直感と違う → 壁時計は端末時刻の目安。正しさは操作順側で見る
4. ビルドや `pnpm check` が緑でも、この 1 週間の記録の代わりにはならない
